ARC contributes the Team companion and display-only browser annotations through the generic experimental thread slots. Core owns project navigation, grouping, nested thread rows and the stable main chat. The existing Workspace plugin route continues to show its own main conversation; the companion renders only team activity, worker timelines and the immutable graph.

`listThreadBindings` is registered with the Workspace RPC contract and available through SDK plugin RPC and `bb arc workspace rpc`. Reads are project scoped, bounded to 100 thread IDs and 100 run summaries per batch, with 1–20 summaries per origin and explicit pagination. The browser publisher divides up to 500 visible rows into bounded requests. It never loads transcripts or workspace preparations. Stored `originThreadId` and effect `thread_id` bindings supply associations; titles and recency do not establish membership.

Workflows supplies an owner-only targeted read for the newest nonterminal run per requested origin. This result is independent of historical pagination and is checked against ARC's immutable run and workflow IDs. When Workflows is unavailable, the response says so and falls back to the latest saved run. Detailed status reads remain bounded and cannot advance execution. Run summaries retain predecessor and successor application linkage, including a successor still awaiting admission.

Publishing a newer agent or team revision does not update any annotation for an existing run. Agent identity, configured execution model, team revision and group color come from the retained compilation. Counts describe admitted worker conversations. They do not imply active inference or total graph stages.

The Team selector prefers the exact run ID in the host-owned `threadViewState.arc/team` URL parameter, then retains explicit user choices in session storage per project/thread, including an off-page run. Core navigation owns URL writes and history; Chat/Team switches preserve the run parameter. ARC validates the run ID and the selected Workspace's parent before displaying it. Opening Team never starts or resumes work. The empty state links to existing Orchestration configuration. Both providers refresh on `runs:changed` and visible-document return. Team run selection refreshes every 15 seconds while mounted; browser annotations refresh every 30 seconds only while an observed run is nonterminal or its lookup failed. Workspace's existing cursor-based polling remains confined to the selected Team view.

New `native-accepted` cursor events animate once from the host-provided main chat anchor to the visible, exact worker pane. The temporary pointer-transparent overlay uses viewport geometry clipped to the common visible chat/team area and is disposed on completion, scrolling, resizing, visibility changes and unmount. Hidden panes and reduced-motion preferences produce no animation; actual assignment status and announcements remain. The anchor is transient UI geometry, never execution identity or authority.
